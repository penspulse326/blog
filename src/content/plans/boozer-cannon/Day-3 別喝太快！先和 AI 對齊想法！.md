前一篇我們談到 AI 的產出經常會附加一些我們不需要的東西，例如：

1. 不需要的功能
2. 不需要的程式碼
3. 不需要的文件說明

等等......四處都有，這是使用 AI 的必然結果，如果不去蕪存菁，就會有很多 AI slop，畢竟 LLM 的本質就是預測後填充，產出的結果**總是有隨機性**。

無論人工檢查還是 AI 檢查，基本上**不太可能完全清乾淨**。其實以前純手工寫出來的也多少有廢 code。因此使用 AI 時就應該要有**擦屁股** （？）的心理建設，slop 的量淡到大家能接受就好。

所以接下來的產出，都要拷問 AI，這些東西怎麼做出來、原因是什麼，減少廢棄物！

## 拷問開始

先前 prompt 給的功能範圍沒有太多，但為了減少走偏的機率，還是要問清楚這是怎麼設計的。

我對表單欄位起初沒什麼想法，現在看到通靈後的結果，我第一個想問的是：

```
關於你設計的表單欄位：

- 建議杯型
- 冰塊類型
- 裝飾物 (Garnish)

這些為什麼這些欄位是設計成文字輸入
```

AI 回復：

```
1. **容納高度多樣性與調酒創意**：相較於基酒與技法有明確分類，杯型（如 Nick & Nora、Tiki 杯）、冰塊（如手鑿長冰、冰球、乾冰）與裝飾物（如炙燒香草、自製果乾）變化無窮，純下拉選單極難窮舉且易扼殺創意。
2. **降低輸入挫折感**：若強制使用固定的下拉選單，調酒師只要使用非典型器皿或自創裝飾，就容易在選單中找不到選項而受阻。
3. **更理想的折衷解法**：實務上最佳體驗是改用 HTML5 `<datalist>` 複合輸入，既能提供常用經典項目供一鍵快選，又能隨時自由手動輸入自訂規格。
```

那麼下一個問題就來了！純文字輸入就很難確保使用者給的東西是好查詢的。

我預想的解法是要有上面 AI 回復建議的**複合輸入**，類似 Notion 的 Multi select。

資料庫裡面會有一份定期維護的中英文對照，當作選項給使用者選，也可以讓使用者自行輸入。

來看看 AI 的建議：

```
採「**雙軌制 + 智慧聯想**」即可完美兼顧自由度與資料結構：

* **資料庫（別名與標準庫）**：建立標準詞字典（如 `Tanqueray`），並綁定中英文別名（`坦奎利`、`No.10`）。酒譜同時儲存「標準 ID」與「使用者輸入文字」，確保能精準篩選，未列入的自創材料則留空。
* **前端（Autocomplete）**：打字即時跳出標準中英文標籤，點選即標準化，不在選單內也能直接 Enter 自由輸入。
* **搜尋（同義詞展開）**：搜「坦奎利」時自動關聯「Tanqueray」，跨語系精準撈出所有酒譜。
```

和我想得差不多～我暫時也想不到其他解法，至於 UI 操作頻繁觸發 API 之類、怎麼審核使用者的輸入等等實作細節的問題，目前應該不用追那麼深。

（雖然大概看得懂在說什麼，但「雙軌制 + 智慧聯想」聽起來有沒有很 AI？這就是中翻英翻中的 AI 作文 XD
